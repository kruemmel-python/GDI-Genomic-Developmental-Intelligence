# Adaptive experimentation and independent experience training

GDI now has a regulated experimental development path separate from R17--R19 capability selection.

1. `trainAdaptiveExperienceModel` analyses protected projects and persists only project-independent, structurally evidenced principles in a GDI experience model.
2. `runAdaptiveExperimentation` establishes a native baseline and evaluates an external runtime oracle.
3. From observed output and source structure it derives counterfactual hypotheses over genomically authorised token-level operations.
4. Every hypothesis is applied only to a fresh isolated copy, then rebuilt, regression-tested and executed through the actual discovered target.
5. A maximum of 50 hypotheses is enforced. Positive evidence is recorded as reusable experience; failed hypotheses are recorded as negative knowledge and suppressed on a later identical attempt.

The first generic operator grammar is deliberately small: it can infer a unique observable string-literal substitution from an external runtime oracle. This is not a domain class such as CSV, state or crafting and has no project-specific symbol or filename rule. It is nevertheless bounded: problems requiring richer structural changes remain blocked until a future experiment derives and verifies an additional regulated primitive.

The immutable genome authorises training, counterfactual derivation, isolated execution and negative-experience consolidation through static loci 16835--16838. Training data and runtime experience do not mutate the genome.
